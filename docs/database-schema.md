# Database Schema

PostgreSQL 16. All primary keys are UUIDs generated by Postgres's built-in `gen_random_uuid()` (core since Postgres 13 — no `uuid-ossp`/`pgcrypto` extension is actually required for it on Postgres 16, though the initial migration still runs `CREATE EXTENSION IF NOT EXISTS pgcrypto` as a harmless, spec-aligned no-op per section 5's wording, and as a safety net for any environment where it isn't core). Enum columns are native Postgres enums (SQLAlchemy `Enum` type with `values_callable` set to use each Python enum member's `.value`, not its `.name` — `app/core/database.py`), storing lowercase string values (`"admin"`, `"active"`, etc.) matching the API/schemas throughout.

This document describes the schema as actually migrated (`backend/alembic/versions/`), which matches section 5 of the spec plus the minor additions noted inline.

## Entity-relationship summary

```
organizations 1──* users 1──* refresh_tokens
organizations 1──* projects
projects 1──* project_members *──1 users
projects 1──* project_holidays
projects 1──* tasks (self-referential parent_task_id for WBS)
tasks 1──* task_assignees *──1 users
tasks 1──* task_dependencies (predecessor_id/successor_id, both → tasks)
projects 1──* baselines 1──* baseline_tasks *──1 tasks
tasks 1──* worklogs *──1 users
projects 1──* progress_snapshots
```
